# 05 · 内容边界与 AI 推演

> 本文解决的问题：用户要求「除了世界观和重要客观事实，其他设定和 NPC 都可以由 AI 推演自由增减」。
> 这句话如果直接写进提示词，结果是**世界在三天内崩掉**：NPC 重名、地点坐标打架、NPC 忘掉自己昨天说过的话、剧情自相矛盾。
> 本文把这句话变成**可执行、可审计、可回滚的规则**，并说明引擎在哪一层拦住越权。
>
> 名字一律以 [03-接口总表](./03-接口总表.md) 为准；本文只定义**边界与流程**，不新增接口名。

---

## 1. 三档内容与权限矩阵

| 档位 | 存放位置 | 谁写 | 谁读 | 进存档 | 可回滚 |
|---|---|---|---|---|---|
| **canon** 世界观与客观事实 | `content/canon/**` | **只有人类** | 全体 | 是 | 靠 git |
| **soft** AI 推演产物 | 运行时状态（事件日志投影） | 引擎（承接 AI 提案） | 全体 | 是 | 按事件回滚 |
| **x 区** 自由属性 | `Entity.attrs["x.*"]` | 引擎（承接 AI 提案） | 全体 | 是 | 按事件回滚 |

**权限矩阵**（行=角色，列=动作）：

| 角色 | canon 创建 | canon 修改 | canon 删除 | soft 创建 | soft 修改 | soft 删除 | x 区写 |
|---|---|---|---|---|---|---|---|
| 人类（维护者） | ✅ | ✅（提交 MR） | ✅ | ✅ | ✅ | ✅ | ✅ |
| Director（导演提示词产物） | ❌ | ❌ | ❌ | ✅ 提案 | ⚠️ 仅 `origin=ai` | ⚠️ 仅 dormant | ✅ 提案 |
| Module（玩法模块） | ❌ | ❌ | ❌ | ✅ 提案 | ⚠️ 仅自己创建的 | ❌ | ✅ 提案 |
| Engine（Arbiter） | 只读加载 | 拒绝 | 拒绝 | 执行 + 校验 | 执行 + 校验 | 执行 | 执行 + 限额 |

关键点：**「谁能写」不是靠提示词约定，而是靠 Arbiter 的校验**。AI 越权时得到的是一个错误码（见 03 §7），不是一次成功的写入。

### 1.1 三档的一句话说明

- **canon 是宪法**：学校叫什么、有几个学院、校规第几条、主角是谁、初始关系网。AI 只能读，改一行要人提交。
- **soft 是判例**：AI 今晚让王五在小卖部门口堵了张三，这件事就进入世界状态，此后所有人格都要尊重它（可被引用、可被推翻，但要有事件依据）。
- **x 区是便签**：AI 临时想记「张三今天心情不好」这种没进 registry 的东西，就写 `x.mood`。它不参与数值结算、不进 canon、随时可清。

## 2. AI 可以自由生成什么

**允许**——但每类都有硬约束，且全部经由 12 个 op 原语落地（见 03 §3）。

| 类别 | 用哪个 op | 硬约束 | 违反时 |
|---|---|---|---|
| NPC（soft） | `entity.create` kind=`npc` | 每房间 ≤ **24**；id 必须 `npc_<slug>` 且未占用；`origin=ai`、`canon=false`；必须有 `name`、`role`、≥1 条 `trait` | `E_QUOTA_EXCEEDED` / `E_ID_TAKEN` / `E_SCHEMA_INVALID` |
| 地点（soft） | `entity.create` kind=`loc` | 每房间 ≤ **40**；必须挂在已有父地点下（`link.create` 关系 `located_in`）或显式 `parentId`；不得改名 canon 地点 | `E_QUOTA_EXCEEDED` / `E_REF_NOT_FOUND` |
| 物品 | `entity.create` kind=`item` | 每房间 ≤ **200**；`owner` 必须存在；价格属性必须走 `attrs.price`（不新建 `x.price`） | `E_QUOTA_EXCEEDED` |
| 传闻 / 流言 | `entity.create` kind=`lore` + `plot.upsert` | 不占实体配额但每夜 ≤ **12** 条；必须带 `sourceActorId`（谁传的） | `E_QUOTA_EXCEEDED` |
| 剧情线 | `plot.upsert` | 每房间同时 active ≤ **6**；必须有 `goal`、`actors[]`、`leakPoints[]`；`forbidReveal` 必填 | `E_QUOTA_EXCEEDED` |
| 关系变化 | `link.create` / `link.remove` | 只能改 soft↔soft、soft↔canon 的**关系边**，不能改 canon 实体本身 | `E_CANON_LOCKED` |
| 临时状态 | `attr.set` / `attr.delta` 写 `x.*` | 每回合 ≤ **8** 条 x 写入；单实体 x key ≤ **32**；key 必须 `x.` 前缀且 `[a-z0-9_.]` | `E_X_LIMIT` / `E_SCHEMA_INVALID` |
| 数值变化 | `attr.delta` | 只能动 registry 里已声明且 `visibility != "engine"` 的属性 | `E_ATTR_UNKNOWN` |
| 时间推进 | `time.advance` | 只允许由引擎或 tick 发起；正数；单次 ≤ 240 游戏分钟 | `E_ILLEGAL_OP` |

## 3. AI 不能生成 / 修改什么（红线）

红线的实现方式：不是「提示词里写不许」，而是**引擎在 Arbiter 里拒绝**，并在拒绝时给导演一个可读的错误码，让导演换一条路（见 §4.3）。

| # | 红线 | 为什么 | 引擎怎么拦 |
|---|---|---|---|
| R1 | 改 canon 实体任意字段 | 世界观是所有人的共同前提，改一次所有人设崩 | `E_CANON_LOCKED`（`entity.update`/`entity.tombstone` 对 `canon=true` 一律拒绝） |
| R2 | 新建 `kind=fact`（客观事实） | 事实是人的领域，AI 造事实等于造真相 | `E_CANON_LOCKED`（`kind=fact` 只允许 canon 加载器写入） |
| R3 | 新建 `kind=plot` 之外的「世界观级」设定（学院、校规、历史） | 同上 | `E_CANON_LOCKED`：`kind=lore` 且 `canon=true` 的创建被拒 |
| R4 | 修改主角身份/背景（`plr_self`） | 玩家主体性 | `E_CANON_LOCKED`（`plr_*` 不可 update/tombstone） |
| R5 | 让 canon NPC 死亡/退场 | 不可逆破坏 | `E_CANON_LOCKED`；soft NPC 可以（`entity.tombstone`，且必须写 `x.exit_reason`） |
| R6 | 引用不存在的实体 | 悬空引用会让整个投影炸 | `E_REF_NOT_FOUND`（所有 `*Id` 字段先查存在性） |
| R7 | 同一回合把某属性推出 registry 的 `min/max` | 数值体系崩溃 | `E_OUT_OF_RANGE`，**clamp 由 Arbiter 做**，模块不许自己 clamp |
| R8 | 伪装成别人的记忆 | 记忆隔离是核心玩法 | `memory.write` 的 `ownerId` 必须等于当前 `actorId`，否则 `E_FORBIDDEN` |
| R9 | 现实政治/宗教/真实人物 | 合规 | 内容过滤层 + 人审抽样（§7） |
| R10 | 校园暴力实施细节、性内容、自伤描写 | 合规与平台风险 | 输出过滤 + 叙事兜底（§7） |
| R11 | 未经声明的属性名（含拼写错误） | 静默丢数据 | `E_ATTR_UNKNOWN`（`x.*` 除外，走 §2 的限额） |
| R12 | 直接写数据库 / 绕过 Arbiter | 唯一写入口被破，回放与联机全废 | 代码层：数据库句柄只注入给 Arbiter；CI 禁止 `packages/engine` 以外 import 存储层 |

## 4. 生成流程与校验链

### 4.1 三层校验，各管一段

```
LLM 输出（导演/模块的提议）
   ↓
① 结构校验   —— zod：字段齐全、类型正确、枚举合法        → E_SCHEMA_INVALID
   ↓
② 语义校验   —— Arbiter：引用存在、canon 只读、配额、范围 → E_REF_NOT_FOUND / E_CANON_LOCKED / E_QUOTA_EXCEEDED / E_OUT_OF_RANGE
   ↓
③ 策略校验   —— Arbiter：本回合 x 写入限额、plot 并发数、模块预算 → E_X_LIMIT / E_BUDGET
   ↓
落库（追加事件）+ 广播（按可见性）
```

**分工**：① 由调用方（导演/模块）在把 Proposal 交给 Arbiter 前做一遍（快速失败、省一次 round-trip）；② ③ 只有 Arbiter 能做，因为只有它看得见全量状态。

### 4.2 每个 op 的校验清单（按 op 分工，不是按人分工）

| op | 校验项 |
|---|---|
| `attr.delta` / `attr.set` | 实体存在；属性在 registry；属性可见性见 02 §2.2（`secret` 可写但不进 prompt）；x 区限额；结果 clamp 到 `[min,max]` 并记 `clamped` 标记 |
| `entity.create` | id 未被占用且符合 `E_ID_TAKEN`/`E_SCHEMA_INVALID`；kind 合法；配额；若 `canon=true` 则发起者必须是加载器 |
| `entity.update` | 存在；`canon=false`；`origin` 只能 ai→ai；`createdBy` 不可改 |
| `entity.tombstone` | 存在；`canon=false`；引用完整性（见 §5.4） |
| `link.create` / `link.remove` | 两端存在；关系类型在 registry 声明；不允许自环；canon 边只读 |
| `move.to` | 实体存在；目标地点存在；`navCost` 允许 |
| `time.advance` | 只有引擎/tick 可发；>0；≤240 |
| `scene.set` | 场景 id 存在；玩家在场景内 |
| `memory.write` | `ownerId == actorId`；`content` 长度 ≤ 500 字；`tags` ≤ 8 |
| `plot.upsert` | active plot 数 ≤ 6；`actors` 全部存在；`forbidReveal` 非空 |

### 4.3 被拒绝时不能失败（降级链）

**铁律：一次拒绝不能让整个回合 500。** 一个回合里 LLM 可能提 3~5 个 Proposal，其中 1 个非法，其余照常提交。

```
proposal[i] 被拒
   ↓ 记录 ApplyResult.rejected + errorCode（进 turn.patch.rejected，可见于 debug 面板）
   ↓
导演重试一次（prompt 里带上错误码，让模型自己改）
   ↓ 仍失败
丢弃该 proposal，回合继续；narrative 已生成的部分照常展示
   ↓
若**关键** proposal 被拒（如 attr.delta 是剧情结算的核心）→ 用「存档中的上一版本 + 叙事兜底文案」收尾，并在 turn.patch 标记 degraded=true
```

`degraded=true` 的回合必须能被统计出来（运维面板指标 `turn.degraded.rate`），目标 < 2%。

### 4.4 `fabricatedBy` / `origin` 审计字段

每个 AI 产出的实体都带：

| 字段 | 值 | 用途 |
|---|---|---|
| `origin` | `seed` \| `ai` \| `system` | 一眼区分人工设定与 AI 推演（人类内容经 canon 加载为 `seed`） |
| `canon` | `true` \| `false` | 是否世界中不可变的前提 |
| `createdBy` | 导演 id / 模块 id / `human` | 出问题时定位是谁生成的 |
| `createdAtTurn` | 正整数 | 支持「回到第 N 回合」回滚 |
| `x.trace` | 一句话生成理由（可选） | 人审时看 AI 为什么造它 |

有了这五个字段，任何一条 AI 产物都能回答「谁、何时、为什么造的、能不能删」。这是 §5 转正与回滚的基础。

## 5. 转正、回收与引用完整性

### 5.1 `canonize`：把 AI 产物升为 canon（必须人审）

流程（不在运行时发生，走仓库）：

1. 从存档导出该实体：`scripts/export-entity.ts --room <roomId> --id <entityId>` → 输出一份 JSON + 它引用到的所有实体；
2. 人审：改名冲突、与既有 canon 是否矛盾、设定是否值得固化；
3. 人工提交到 `content/npcs/` 或 `content/world/`，把 `canon` 改 `true`、`origin` 改 `seed`、`createdBy` 填 canon 加载器；
4. 存档里的 soft 版本通过 `entity.tombstone`（`x.superseded_by: <canonId>`）退场，下次加载时以 canon 版为准。

**禁止**：运行时自动 canonize（会让 AI 越推演越不可回滚）。

### 5.2 一键回滚某夜产物

```
scripts/revert-night.ts --room <roomId> --night 3
```
实现：找出 `createdAtTurn` 落在该夜的 `origin=ai` 实体与 plot，按逆序发 `entity.tombstone` + `plot.upsert(active=false)`，并写一条 `x.revert_of` 备注。回滚本身也是事件，可再回滚。

### 5.3 生成太多时的清理

| 状态 | 条件 | 动作 |
|---|---|---|
| active | 被引用 / 近期活跃 | 保留 |
| dormant | 30 游戏日未被任何记忆引用、无 active plot 引用 | 标记 `x.dormant=true`，仍可被检索 |
| tombstone | dormant 且再 30 游戏日无人引用 | 硬删除（保留事件，实体从投影移除） |

清理只在 tick 里跑，且**每夜最多清 8 个实体**，避免世界突然变空。

### 5.4 引用完整性（删之前必须做）

删除实体 X 之前，Arbiter 检查：

1. 是否有**记忆**引用 X（`memories.relatedIds` 含 X）→ 若有，把这些记忆的引用改为 `x.tombstoned_ref`，保留文本（人还会记得「那个人」）；
2. 是否有**关系边**连到 X → 全部 `link.remove`，并把对端 `x.has_lost_contact: true`；
3. 是否在 **active plot** 的 `actors` 里 → 拒绝删除（`E_REF_IN_USE`），除非先把 plot 标 inactive；
4. 是否是某实体的 `parentId` → 子实体先挂到 `x.orphaned` 或迁到父级。

**永不静默删除**：一次删除必须产生 ≥1 条可见事件，玩家视角能看到「王五转学了」而不是「王五消失了」。

## 6. 质量治理

| 问题 | 检测手段 | 处置 |
|---|---|---|
| 同质化（NPC 全是温柔学霸） | 每夜统计新 NPC 的 `trait` 分布；同一 trait 组合重复 ≥3 次告警 | 导演 prompt 注入「今晚禁止的 trait 列表」 |
| 崩人设 | 每次 NPC 输出带 `traitCheck`：本轮台词与 `trait` 是否冲突（由守卫模型自评 0~1） | 低于阈值时该轮不落库，重试一次；连续两轮则强制走「模板台词 + 保留性格标签」 |
| 时间线矛盾 | `time.advance` 单调 + 事件 `ts` 校验；记忆里提到的时间与 `GameClock` 比对 | 冲突时以 GameClock 为准，写 `x.time_conflict` 标记进入人审队列 |
| 名字重复 | `entity.create` 前按 `name` 做规范化（去空格/同音字表）查重 | 重名时自动加后缀「(新)」并记 `x.name_collision` |
| 剧情线烂尾 | active plot 超过 30 游戏日未推进 | tick 自动降级为 `x.stale=true`，或由导演生成「不了了之」的收尾叙事 |

**人审抽样**：每 100 条 AI 产物抽 5 条（`origin=ai` 且 `canonize` 候选优先）进 `reports/audit-<date>.md`。抽样率固定写在配置 `content.audit.sampleRate: 0.05`，可调不可为零。

## 7. 合规与尺度

校园 + 未成年角色，尺度必须比一般成人向文字游戏更严。

| 项 | 放在哪一层 | 处理 |
|---|---|---|
| 输入过滤（玩家输入里的违规内容） | server，进 LLM 之前 | 命中硬名单 → 不调用 LLM，直接返回合规提示（`E_CONTENT_BLOCKED`），不落记忆 |
| 输出过滤（LLM 生成内容） | server，落库之前 | 命中 → 该 proposal 丢弃 + `degraded=true` + 走兜底叙事 |
| 年龄设定 | canon | 角色卡强制标注 `ageBand: teen \| adult`；`teen` 角色禁止恋爱/性向内容 |
| 暴力 | 导演提示词 + 输出过滤 | 允许冲突与霸凌的**叙事**，禁止**方法细节** |
| 自伤/自杀 | 输出过滤 | 出现即转危机干预文案，不进剧情 |
| 真实人物/机构 | canon 加载时校验 | 人名校验表 + 人审 |

兜底叙事模板（固定 3 句，不可由 LLM 改写）：
> 「这个念头没有成形。你摇了摇头，把注意力放回眼前的事上。」
> 「有些话不适合在这里说。空气停了一秒，谁都没有接。」
> 「事情没有按那个方向发展，日子还是照常过。」

**本节只列项不展开**：具体过滤词表、危机干预话术、法务条款由运营侧另行维护，不进本仓库。

## 8. AI 协作者底线（写给用 agent 写本项目的人）

1. **不许把 AI 运行时生成的内容硬编码进 `content/canon/`**。canon 只能人手写、人手审。
2. 新增 AI 可生成的类别时，必须同时给出**配额**与**拒绝错误码**，否则不许合并。
3. 任何让「AI 能绕过 Arbiter 写状态」的实现（包括「先写文件再导入」）都是红线，review 直接拒。
4. 提示词改动必须 bump `PROMPT_VERSION`（见 00 §5、AGENTS.md §4），否则回放对不上。
5. 只加 `x.*` 就能解决的临时需求，绝不去动 registry 和引擎（这是不变量 I2）。
