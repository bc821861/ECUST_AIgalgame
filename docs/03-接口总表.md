# 接口总表（Contract Index）

> **本文是唯一"名字"来源**。任何文档、代码、提示词里出现的接口名、op 名、事件名、字段名，都必须能在本文查到。
> 查不到的名字 = 未定义 = 不许用。新增接口必须先改本文，再写代码。
> `CONTRACT_VERSION: 2.2.0` ｜ 变更本文件中任何一节的语义 → 必须 bump 的版本号见 §0.6。

## 0. 命名总则

### 0.1 六条规则

| # | 规则 | 反例 |
|---|---|---|
| R1 | **点分命名空间**：`<ns>.<verb>`，全小写，单词用 `_` 连接 | `buyItem` / `Trade.buy` |
| R2 | **名词用单数**，不用复数 | `items.list` ✗ → `item.list` ✓ |
| R3 | **动词用祈使式**，不加时态 | `bought` ✗ → `buy` ✓ |
| R4 | **模块内接口必须带模块 id 前缀**：`<moduleId>.<verb>` | 模块 `trade` 的工具只能叫 `trade.*` |
| R5 | **保留命名空间禁止被模块占用**（见 §0.2） | 模块不能叫 `mod` / `npc`；唯一例外是引擎自带的基础动作模块 `content/modules/core` |
| R6 | 名字一旦随版本发布，**只增不改不删**；废弃用 `deprecated` 标记并保留 ≥2 个版本 | 直接把 `trade.buy` 改名 |

### 0.2 保留命名空间

| 命名空间 | 归属 | 用途 |
|---|---|---|
| `core` | 引擎 | 移动/观察/等待/说话等基础动作（实现放在 `content/modules/core`，属于引擎自带模块，其他模块不得占用该前缀） |
| `world` | 引擎 | 时钟、地点、天气、事件 |
| `actor` | 引擎 | 玩家/NPC 通用能力（任何 actor 都能做） |
| `npc` | 引擎 | 自主行为、对话调度 |
| `mem` | 引擎 | 记忆读写 |
| `plot` | 引擎 | 剧情线/密谋 |
| `mod` | 引擎 | 模块元操作（`mod.load`、`mod.reload`） |
| `net` | 引擎 | 房间、成员、同步 |
| `view` | 引擎 | 视图数据下发 |
| `admin` | 引擎 | 仅本机/内网 |
| `x` | **AI 自由区**（见 §0.5） | AI 推演时临时产生的属性/标记 |

> 模块 id 不得与上表重名（启动时校验，冲突即拒绝启动）。

### 0.3 实体 ID 规范

```
<kind>_<slug>              例：npc_zhangsan, loc_classroom_2_3, item_bread
<kind>_<slug>_<n>          需要区分实例时：mem_1a2b3c, plot_0007
```

| kind | 含义 | 谁创建 |
|---|---|---|
| `plr` | 玩家 | 引擎 |
| `npc` | 非玩家角色 | 内容种子 / AI 推演 |
| `loc` | 地点 | 内容种子 / AI 推演 |
| `item` | 物品 | 内容种子 / AI 推演 |
| `fact` | 客观事实（canon） | 仅人工 |
| `lore` | 软设定（AI 可增删） | 内容种子 / AI 推演 |
| `plot` | 剧情线/事件 | AI |
| `mem` | 记忆条目 | 引擎 |
| `evt` | 事件（日志） | 引擎 |
| `room` | 房间（单人/联机） | 引擎 |
| `mod` | 模块实例 | 引擎 |

- `slug` 只允许 `[a-z0-9_]`，长度 2~32；中文名只存在 `name` 字段里，**不进 id**。
- ID 全局唯一，**永不复用**（删除 = `tombstone`，见 `02-数据格式.md` §6）。

### 0.4 版本号

| 东西 | 字段 | 语义 |
|---|---|---|
| 接口契约（本文） | `CONTRACT_VERSION` | 语义化版本；破坏性变更 → major |
| 模块 | `manifest.apiVersion` | 整数，引擎只认 `1`（v2 起为 `2`，见下） |
| 数据格式 | `schemaVersion` | 每个 schema 文件内 `$id` 尾段 |
| 事件 | `v` | 事件 payload 形状版本，默认 `1` |

> `apiVersion` 变更策略：**只有当 §3 的 op 原语集合变化时才 bump**。新增模块/工具/属性/事件类型**永不** bump（这就是"只加变量不改引擎"的机制保证）。

### 0.5 `x.` 自由区（AI 推演专用）

AI 在推演中产生的**临时属性/标记**一律放进 `x.` 前缀：

```json
{ "op": "attr.set", "args": { "entityId": "npc_zhangsan", "key": "x.mood_hint", "value": "躲闪" } }
```

- 引擎对 `x.*` **不做类型校验**，按 `number | string | boolean` 原样存。
- `x.*` 只能在**本房间内**可见，不进 canon、不进全局检索、**不得被叙事层当作硬事实引用**。
- 每回合 `x.*` 写入上限 8 条；单实体上限 32 个 key（超出按 LRU 淘汰）。
- 想让某个 `x.*` 转正 → 人工在 `content/registry/attrs.json` 声明正式 key，然后 `attr.set` 迁移。

> 这条是"AI 可以自由增减，但引擎不被污染"的关键闸门。

### 0.6 变更影响矩阵

| 你改了 | 必须做什么 |
|---|---|
| 新增模块 | 加一个目录 + `manifest.json`（启动自动扫描 `content/modules/*/manifest.json`，**无需登记**）。**不动引擎** |
| 新增属性 | `content/registry/attrs.json` 加一条 + UI 字段映射（可选）。**不动引擎** |
| 新增 LLM 工具 | manifest `tools` 加名 + 实现 handler。**不动引擎** |
| 新增事件类型 | `content/registry/events.json` 加一条。**不动引擎** |
| 新增 op 原语 | 本文 §3 + 引擎 `Arbiter` + bump `apiVersion`。**动引擎（尽量避免）** |
| 改 op 语义 | bump `CONTRACT_VERSION` major + 全体模块回归 |

## 1. 分层与名字归属

```
Client ──HTTP/SSE──> Transport ──Envelope──> Router
                                                │
                                             Turn.run
                                                │
                    ┌───────────────────────────┼───────────────────────┐
                 Modules                      Dialogue                 Memory
              (modules/*)                 (directors/*)            (engine)
                    └──────────────► Arbiter.apply ◄─────────────────┘
                                          │
                                     EventLog / Snapshot
```

- **只有 `Arbiter.apply` 能写世界状态**。模块、导演、记忆、UI 全部产出 `Proposal[]`。
- **只有 `Transport` 接触网络**。引擎不知道 HTTP/WS/SSE 的存在，只知道 `Envelope`。

## 2. 内部接口（TypeScript）

> 路径：`packages/shared/src/contract/`。这些类型是**冻结契约**，实现可换，签名不可随意改。

### 2.1 基础类型

```ts
/** 统一信封：所有跨子系统消息都用它 */
interface Envelope<T = unknown> {
  v: 1;                      // payload 版本
  id: string;                // 消息 id（evt_xxx）
  roomId: string;
  seq: number;               // 房间内单调递增，用于去重与断线续传
  ts: number;                // 服务器时间戳 ms
  actorId: string;           // 发起者：plr_* / npc_* / sys
  type: string;              // 见 §5
  payload: T;
  causedBy?: string;         // 触发它的上一条消息 id
}

/** 世界状态 = 实体集合 + 房间元信息 */
interface WorldState {
  schemaVersion: number;
  room: RoomState;
  entities: Record<string, Entity>;   // id -> 实体
  links: Link[];                      // 关系/持有/在场等边
  clock: GameClock;
}

interface Entity {
  id: string;
  kind: EntityKind;                   // plr|npc|loc|item|fact|lore|plot
  name: string;
  attrs: Record<string, AttrValue>;   // 键必须在 registry 或 x. 区
  tags: string[];
  origin: "seed" | "ai" | "system";   // 谁创造的
  canon: boolean;                     // 是否锁定
  status: "active" | "dormant" | "tombstoned";
  createdAt: number;                  // 游戏内回合序号
  updatedAt: number;
}

type AttrValue = number | string | boolean;
```

### 2.2 注册表 `Registry`

```ts
interface Registry {
  attr(key: string): AttrDef | undefined;       // 读属性定义
  attrs(scope?: EntityKind): AttrDef[];         // 某类实体可用属性
  event(type: string): EventDef | undefined;
  intent(name: string): IntentDef | undefined;
  tool(name: string): ToolDef | undefined;
  op(name: string): OpDef | undefined;          // §3 原语
  reload(): Promise<void>;                      // 仅 dev
}
```

### 2.3 裁决器 `Arbiter` —— 唯一写入口

```ts
interface Arbiter {
  /** 校验 + 应用 + 落日志。要么全成功，要么全回滚 */
  apply(roomId: string, ops: Proposal[], cause: Envelope): Promise<ApplyResult>;
  /** 只校验不落库（干跑，给 UI 预览与测试用） */
  dryRun(roomId: string, ops: Proposal[]): Promise<ValidationResult>;
}

interface Proposal {
  op: string;                       // §3 的 12 个原语之一
  args: Record<string, unknown>;    // 每个原语的参数见 §3
  reason?: string;                  // ≤60 字，写进日志便于排查
  by?: string;                      // 产生者：mod.trade / npc.director / engine.turn
}

interface ApplyResult {
  ok: boolean;
  seq: number;                      // 落库后的最新 seq
  applied: Proposal[];
  rejected: { proposal: Proposal; code: ErrorCode; detail: string }[];
  events: Envelope[];               // 本次产生的领域事件
}
```

### 2.4 回合引擎 `Turn`

```ts
interface Turn {
  /** 玩家一次输入 → 一次完整回合（含模块、LLM、裁决、记忆） */
  run(req: TurnRequest): AsyncIterable<TurnEvent>;   // 流式，SSE 直接透传
}

interface TurnRequest {
  roomId: string;
  actorId: string;                  // 谁在行动（联机时可能是 NPC）
  input: string;                    // 自然语言原文
  clientTurnId: string;             // 客户端幂等 id，重复提交返回同一回合
  options?: { debug?: boolean; skipLLM?: boolean; budget?: number };
}

type TurnEvent =
  | { type: "turn.accepted"; turnId: string }
  | { type: "turn.delta"; field: "narrative" | "dialogue"; text: string }
  | { type: "turn.facts"; facts: string[] }             // 模块给出的既成事实
  | { type: "turn.tool"; name: string; args: unknown; result: unknown }
  | { type: "turn.patch"; ops: Proposal[]; state: WorldState }  // 裁决后的增量
  | { type: "turn.ui"; view: ViewPatch }
  | { type: "turn.commit"; turnId: string; seq: number; usage?: Usage }
  | { type: "turn.error"; code: ErrorCode; message: string; retryable: boolean };
```

> `TurnEvent` 的 `type` 就是 SSE 的 `event:` 字段，一字不改。

### 2.5 模块宿主 `Modules`

```ts
interface Modules {
  list(): ModuleInfo[];
  get(id: string): ModuleInfo | undefined;
  /** 分发玩家意图到模块（按 priority 顺序，第一个 ok 的胜出） */
  dispatchIntent(ctx: ModuleContext): Promise<ModuleOutcome>;
  /** LLM 工具调用落地（名字必须是 <moduleId>.<verb>） */

  /** 收集本回合要注入 LLM 的上下文片段（按 token 预算裁剪） */
  context(ctx: ModuleContext, budget: number): ContextSlice[];
  /** 模块自有视图数据（如商店列表） */
  view(modId: string, ctx: ModuleContext): ViewPatch | null;
}
```

### 2.7 对话导演 `Dialogue` —— NPC 自主多 agent 对话的唯一入口

> **密谋、闲聊、课堂讨论、玩家插入对话，全部是 `DialogueDirector` 的不同实现**。引擎只提供会话骨架（谁在场、谁能知道什么、发言顺序、写谁的记忆），不关心剧情是"密谋"还是"八卦"。

```ts
interface Dialogue {
  /** 开一场会话：参与者 ≥1 个 NPC，可含玩家 */
  open(spec: DialogueSpec): Promise<DialogueSession>;
  /** 推进 1 轮（内部可能调用 0~N 次 LLM） */
  step(sessionId: string): Promise<DialogueStep>;
  /** 玩家插入发言（联机/单人通用） */
  interject(sessionId: string, actorId: string, text: string): Promise<DialogueStep>;
  close(sessionId: string, outcome?: string): Promise<DialogueSummary>;
}

interface DialogueSpec {
  roomId: string;
  participants: string[];          // actorId 列表，≥1
  directorId: string;              // 用哪个导演（见下）
  seed?: Record<string, unknown>;  // 导演自有参数（密谋传 plotId）
  maxTurns?: number;               // 默认 3
  visibility?: "private" | "scene";// private=只有参与者知道
}

interface DialogueStep {
  sessionId: string;
  turns: ChatTurn[];               // { actorId, text, emotion, thought? }
  done: boolean;
  proposals: Proposal[];           // 导演产出的状态变更（守卫值、关系等）
}
```

**内置导演（均可替换/新增，不需要改引擎）**：

| `directorId` | 用途 | 何时触发 |
|---|---|---|
| `npc.plot` | 夜间密谋（v1 §6 的编排器） | 夜晚 tick |
| `npc.smalltalk` | NPC 之间随机闲聊（填充世界） | 空闲 tick，低频 |
| `npc.react` | NPC 对某事件的一致/分歧反应 | 事件触发 |
| `npc.player` | 玩家与 1~3 个 NPC 的多人对话 | 玩家主动发起 |
| `npc.debate` | 课堂/会议式多方讨论 | 模块触发 |

## 3. Op 原语（**闭集，12 个**）

> 这是整个系统的"指令集"。新玩法**只能用这 12 个原语组合**，不得新增（新增 = bump `apiVersion`）。
> 每个原语的具体字段、校验规则、事件产出见 `02-数据格式.md` §4。
> **参数形状的机器可读真源是 `packages/shared/src/contract/types.ts` 里的 `XxxArgs` 与 `packages/shared/src/zod/op.ts`**；本表若与它们不一致，以代码为准并请报告（`npm run check:contract` 会拦 op 名与错误码，不拦参数字段）。

| # | op | 参数 | 说明 | 产出事件 |
|---|---|---|---|---|
| 1 | `attr.delta` | `{entityId, key, delta}` | 数值增减（自动 clamp 到 registry 的 min/max） | `attr.changed` |
| 2 | `attr.set` | `{entityId, key, value}` | 直接赋值（字符串/布尔/枚举） | `attr.changed` |
| 3 | `entity.create` | `{id, kind, name, attrs?, tags?, origin?, canon?}` | 新建 NPC/地点/物品/传闻（扁平字段，见 `EntityCreateArgs`） | `entity.created` |
| 4 | `entity.update` | `{entityId, name?, tags?, status?}` | 改名字/标签/状态（canon 与 plr 实体的身份字段只读） | `entity.updated` |
| 5 | `entity.tombstone` | `{entityId, reason}` | 软删除（保留引用，见 §6.3） | `entity.tombstoned` |
| 6 | `link.create` | `{kind, from, to, weight?, audience?}` | 建关系边（`knows`/`owes`/`holds`/`present`/`located_in`/`member_of`） | `link.created` |
| 7 | `link.remove` | `{linkId?, kind?, from?, to?}` | 断关系（至少给 `linkId` 或 `kind+from+to` 之一） | `link.removed` |
| 8 | `move.to` | `{actorId, locId, via?}` | 移动（校验邻接；NPC 也用它） | `actor.moved` |
| 9 | `time.advance` | `{ticks?, phase?}` | 推进回合数与时段（只有引擎身份可提，模块提 → `E_ILLEGAL_OP`） | `clock.advanced` |
| 10 | `scene.set` | `{locId?, presentIds?, props?}` | 设定当前场景与在场者 | `scene.changed` |
| 11 | `memory.write` | `{ownerId, content, tags?, salience?, visibility?, about?}` | 写记忆（只能经由 Turn/导演骨架，模块提 → `E_FORBIDDEN`） | `memory.written` |
| 12 | `plot.upsert` | `{id?, goal, actors, leverage?, risk?, tone?, leakPoints?, forbidReveal?, status?, guard?}` | 建/更新剧情线（不传 `id` 则新建） | `plot.upserted` |

**拒绝规则（引擎统一执行，模块不用重复写）**：

| 情况 | 结果 |
|---|---|
| `key` 未在 registry 且不以 `x.` 开头 | `E_ATTR_UNKNOWN`，丢弃该条 |
| `entityId` 不存在或 `tombstoned` | `E_ENTITY_MISSING`，丢弃 |
| `move.to` 目标不邻接 | `E_NOT_ADJACENT`，丢弃并回 `scene` 兜底 |
| canon 实体被 `entity.update` 改 `name`/`attrs` 白名单外字段 | `E_CANON_LOCKED`，丢弃 |
| 单回合同实体同 key 的 `attr.delta` 累计超 registry 的 `maxDeltaPerTurn` | clamp + 记 `clamped` |
| 数组长度超 manifest 声明上限 | `E_OVER_LIMIT`，截断 |

## 4. 领域事件类型（`content/registry/events.json` 声明）

| type | 何时发 | 谁消费 |
|---|---|---|
| `attr.changed` | 任何 attr 变化 | UI、记忆、模块 |
| `entity.created` / `entity.updated` / `entity.tombstoned` | 实体生命周期 | UI、检索索引 |
| `link.created` / `link.removed` | 关系变化 | 密谋导演、UI |
| `actor.moved` | 移动 | 场景、在场者 |
| `clock.advanced` | 时段推进 | 所有模块 `onTick` |
| `scene.changed` | 场景切换 | UI、对话可用性 |
| `memory.written` | 记忆落库 | 压缩任务 |
| `plot.upserted` / `plot.resolved` | 剧情线变化 | 通知、痕迹生成 |
| `guard.changed` | 戒备值变化 | 表现层 |
| `npc.spoke` | NPC 发言（会话内） | 联机广播、日志 |
| `turn.committed` | 一回合结束 | 存档、统计 |
| `room.member.joined` / `room.member.left` | 联机成员变化 | 在场者重算 |

> 新增事件类型 = `events.json` 加一条 + 选择"是否需要广播给客户端"。**不改引擎**。

## 5. 协议层（HTTP / SSE / WS）

### 5.1 原则

- 所有响应体统一 `{ ok: boolean, data?, error?: { code, message } }`。
- 所有流式用 `Envelope`，`event:` 即 `type`，`data:` 即 JSON 序列化的 `Envelope`。
- **无状态请求 + seq 续传**：断线重连带 `Last-Event-ID`（= seq），服务器补发缺失事件。这条是联机的地基。

### 5.2 HTTP（当前，`/api/v1`）

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/room` | 建房（solo/coop/pvp） |
| `GET` | `/api/v1/room/:id` | 拉全量状态 + 当前 seq |
| `POST` | `/api/v1/room/:id/join` | 加入（联机） |
| `POST` | `/api/v1/room/:id/leave` | 离开 |
| `POST` | `/api/v1/room/:id/turn` | **提交行动（SSE 响应）** |
| `GET` | `/api/v1/room/:id/stream` | 订阅事件流（SSE，支持 `Last-Event-ID`） |
| `GET` | `/api/v1/room/:id/events?from=&limit=` | 补历史事件 |
| `POST` | `/api/v1/room/:id/dialogue` | 开一场 NPC 对话会话 |
| `POST` | `/api/v1/dialogue/:sid/interject` | 玩家插入会话 |
| `POST` | `/api/v1/room/:id/save` | 存档 |

### 5.5 视图协议 `View`（服务端下发，前端纯渲染）

```ts
interface ViewPosition {
  locationId: string; name: string; present: { id: string; name: string }[];
  exits: { to: string; label: string; costs: number }[];
  timeLabel: string;                    // "周五 · 傍晚"
}

interface ViewPatch {                    // 增量：只带变化的键
  position?: ViewPosition;
  panel?: Record<string, { label: string; value: number | string; delta?: number }>; // 数值面板
  choices?: { id: string; label: string; hint?: string }[];   // 可选，不是必须
  media?: { portrait?: string; background?: string; cg?: string };
  modals?: { modId: string; kind: string; data: unknown }[];  // 模块自有弹窗
}
```

> **关键**：面板字段从 `registry` 读（`display` 配置），前端不认识任何具体属性名。新增属性 → 面板自动多一行，前端零改动。

## 6. LLM 工具名（function calling）

- 格式严格 `<moduleId>.<verb>`，例：`trade.buy`、`study.quiz`、`social.gift`。
- 引擎工具（非模块）用保留命名空间：`core.move`、`core.observe`、`core.wait`、`core.say`、`actor.emote`。
- 每个工具必须有：`description`（≤120 字）、`parameters`（zod → JSON Schema）、`costWeight`。
- 工具返回统一 `{ ok, facts: string[], proposals: Proposal[] }`。
- 注入策略：只注入"当前地点 + 在场者"相关模块的工具，且总数 ≤ 24 个（超了按 manifest `priority` 截断，防止工具表膨胀）。

**三条权威性判定**（此前有歧义）：
1. `SceneState.presentIds` 是「谁在场」的**唯一真源**；`present` 边是它的投影，由 `scene.set` / `move.to` 后**引擎自动重建**，模块直接 `link.create(kind="present")` → `E_ILLEGAL_OP`。

3. `guard` 是 registry 声明的正式属性，`visibility: "secret"`（值不进 prompt，只以行为分档表现，见 04 §7）。
